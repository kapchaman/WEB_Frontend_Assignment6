## Главная схема

`data.js` хранит исходные данные → `app.js` строит HTML через jQuery → `cases.js` ищет уже созданные элементы → `motion.js` добавляет анимации второй части.

Массив — это данные. DOM — это HTML-элементы, которые браузер показывает на странице. В этом задании **искать гостей нужно в DOM**, поэтому кейсы используют `$('.guest...')`, а не `rooms.filter(...)`. Массив используется для построения страницы и сохранения перемещений.

## Что хранится у гостя

```js
{ name: 'Askar', color: 'black', arrival: '21:00',
  aitu: true, things: ['phone'] }
```

После `makeGuest()` это кнопка с классами `guest color-black aitu has-phone` и атрибутами `data-name="Askar"`, `data-arrival="21:00"`, `data-minutes="1260"`.

`21 * 60 = 1260`: минуты удобно сравнивать числами. `+$(this).attr('data-minutes')` превращает строку из атрибута в число.

## Селекторы и обход DOM

| Код | Простое объяснение |
|---|---|
| `$('#hall .guest')` | Гости внутри hall |
| `$('.guest.aitu')` | У одного элемента есть оба класса |
| `$('.color-yellow, .color-purple')` | Жёлтые ИЛИ фиолетовые |
| `.not('.has-bag')` | Исключить тех, у кого сумка |
| `.filter(function () { return условие; })` | Оставить только элементы, для которых условие true |
| `$(this)` | Текущий HTML-элемент, обёрнутый в jQuery |
| `.prev()` / `.next()` | Один сосед слева / справа |
| `.nextAll()` | Все следующие соседи |
| `.siblings()` | Все соседи на том же уровне |
| `.closest('.room')` | Ближайшая родительская комната |
| `.has('.has-cup')` | Комнаты с подходящим потомком |
| `.add(...)` | Объединить два набора элементов |
| `:nth-child(3)` | Третий ребёнок, отсчёт с 1 |
| `.length` | Сколько элементов найдено |

`filter(function () {...})` нужен обычный `function`, чтобы `this` был проверяемым DOM-элементом. У стрелочной функции собственный `this` не появляется.

Цепочка — последовательность jQuery-методов, каждый из которых возвращает набор элементов для следующего метода. В кейсе 9 две ветки соседей объединяются через `.add()` в один итоговый набор.

## Анимации

```js
$guest.animate({ top: -10 }, 140).animate({ top: 0 }, 160);
```

Сначала вверх на 10 пикселей за 140 мс, затем обратно за 160 мс. `position: relative` позволяет двигать карточку через `top`.

- `fadeIn(350)` — показать с появлением.
- `fadeOut(350, callback)` — скрыть; callback сработает после окончания.
- `fadeTo(300, 0.2)` — за 300 мс сделать opacity равной 20%.
- `remove()` — удалить DOM-элемент, а не просто скрыть.
- `stop(true, false)` — убрать очередь и остановиться в текущей точке; старый callback не выполняется.
- `stop(true, true)` — убрать очередь и закончить текущую анимацию сразу.
- `finish()` — закончить всю очередь, включая ожидающий `fadeOut` и его `remove()`. Поэтому Clear или сортировка не отменяют уход Natasha.
- Сортировка использует отдельную очередь `layout`: её остановка не прерывает эффекты кейса.

В кейсе 19 сначала прыжок, затем fadeOut, затем remove. Удаление очищает данные очереди jQuery, поэтому код не ждёт `.promise()` на уже удалённой карточке: окончание отмечается прямо в callback.

## Карточка гостя

`offset()` даёт координаты относительно документа. Для фиксированного окна вычитаем прокрутку. Панель начинается с координат и размеров аватара и через `.animate()` получает размер 410 × 382 и позицию по центру. При Esc или клике снаружи происходит обратная анимация.

`currentName` — кто открыт сейчас; `requestedName` — кого пользователь хочет открыть; `closing` — закрывается ли окно. Пока оно закрывается, следующий клик меняет только `requestedName`. Поэтому в конце откроется последний выбранный гость, а не очередь всех прошлых.

## Перемещение

1. Удаляем гостя из всех массивов комнат и добавляем один раз в конец новой. Это важно для Miras: кейс 18 может временно поставить его рядом с Askar, хотя сохранённая комната уже другая.
2. Создаём визуальную копию через `.clone()`.
3. На старом месте оставляем промежуток той же ширины; в новой комнате создаём промежуток шириной 0.
4. Копия летит через `.animate({left, top})`, старый промежуток сужается, новый расширяется.
5. Копию убираем, настоящую карточку ставим в новую комнату.

`finishMove` заканчивает незавершённое перемещение перед конфликтующим действием. Если обновлять только HTML, следующий `render()` вернул бы гостя назад — поэтому нужен и массив.

## Сортировка без прыжка

Код запоминает текущие координаты каждой карточки. Потом переставляет элементы в DOM, вычисляет новые координаты и задаёт компенсирующие `left` и `top`, чтобы визуально карточка осталась на прежнем месте. Анимация сводит эти смещения к нулю: карточки едут к новым местам.

При новом клике старые анимации останавливаются, но координаты берутся из текущего положения. Булева переменная `sorted[id]` меняется **при каждом клике**, поэтому пять кликов из исходного состояния дают отсортированный порядок. Переупорядочивание DOM не меняет исходный массив — второй клик может его восстановить.

## События

```js
$('#house').on('click', '.guest', function () { ... });
```

Это делегирование: обработчик на постоянном контейнере ловит клики по гостям, даже если их создали заново. Прямые обработчики на старых карточках исчезли бы вместе с ними при `render()`.

`event.stopPropagation()` останавливает всплытие клика по гостю к обработчику документа. Иначе общий обработчик клика снаружи мог бы сразу начать закрывать карточку.

`version` защищает от устаревших callbacks: если уже запущен следующий кейс, предыдущая анимация не должна менять его результат.
